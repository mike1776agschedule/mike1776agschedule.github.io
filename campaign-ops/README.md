# Campaign Ops — Florida Sign Operations

Statewide (67-county) campaign signage operation. The boss's audited master
workbook is the source of truth; this project layers a small number of scripts
on top to keep the master live.

## Files

- `outputs/campaign_ops_master.xlsx` — **THE master workbook**. Originated
  from the boss's `florida_sign_operations_master_email_complete_double_audited.xlsx`.
  Update by re-copying a newer version from the boss into this path, then running refresh.
- `data/raw/florida_gop_directory.xlsx` — staged copy of the Florida GOP directory
  (898 contacts × 67 counties, audited April 2026). Drop in newer versions here.
- `outputs/sign_candidates_map.html` — interactive Folium map of the 4×8
  deployment plan (and the replacement bench). Open in any browser.

## Master Workbook Sheets

**Boss-owned (read-only except for feedback-loop columns):** 14 sheets
including `Overview`, `County_Master` (67 counties × 34 cols),
`Partners`, `County_Source_Log`, `County_Audit`, `Influence_Prospects`,
`Political_Committee_Leads`, `Top_Target_Counties`, `Priority_Call_List`,
`Regional_Hubs`, `Sign_Site_Playbook`, `Outdoor_Advertising_Leads`,
`Audit_1_Data`, `Audit_2_Operational`.

**User-edited (you fill these in; never overwritten):**
| Sheet | Purpose |
|---|---|
| `Yard_Sign_Deliveries` | one row per yard-sign delivery event |
| `Large_Sign_Locations` | one row per 4x8 site you've actually installed |
| `Outreach_Log` | one row per outreach attempt |

**Derived (regenerated by scripts):**
| Sheet | Source | Purpose |
|---|---|---|
| `Dashboard` | `refresh_master.py` | live KPI rollups: deployment, tier coverage, POC readiness |
| `Directory_Audit` | `refresh_master.py` | cross-walks the GOP directory against County_Master |
| `Sign_Location_Candidates` | `find_sign_locations.py` + `enrich_pocs.py` | full ~3,000-row OSM-derived candidate pool with phone / email / website POCs |
| `Sign_Deployment_Plan` | `select_sign_deployment.py` | the actual **2,000 primary** sign sites + ~500 replacement bench, ranked per county |
| `Yard_Sign_Allocation` | `allocate_yard_signs.py` | per-county yard sign allocation with TWO totals (boss's 7,485 + new Plan_4000) and full POCs |
| `QC_Report` | `qc_report.py` | quality control report — exclusions, totals, POC coverage, hallucination check |

The feedback loop also writes back into specific cells of `County_Master`:
- `Yard Signs Delivered` ← sum of `Yard_Sign_Deliveries.Qty Delivered` by county
- `Yard Signs Remaining` ← `Suggested - Delivered`
- `4x8 Confirmed` ← count of `Large_Sign_Locations` rows where Install Status = 'Installed'

## Categorical Exclusions (V3 Strategist Pass)

Per political-sign-placement reality, these venues are **excluded from the
candidate pool entirely** because they refuse / cannot host political signs:

- **Churches / places of worship** — 501c3 risk
- **Funeral homes** — sensitivity
- **Schools, colleges, universities, kindergartens** — Florida law
- **Government buildings**: post offices, fire stations, town halls, libraries, courthouses, police
- **Banks, ATMs, pharmacies, hospitals, clinics** — corporate policy / sensitivity

Plus a **chain blocklist** of corporate-controlled venues that consistently
refuse political signs: Lowe's, Home Depot, Discount Tire, Firestone, Pep Boys,
Walmart, Target, Costco, Sam's, BJ's, big dollar stores, big grocery (Publix,
Winn-Dixie, Kroger), CVS / Walgreens / Rite Aid, Wawa, RaceTrac, 7-Eleven,
Circle K, Buc-ee's, Bass Pro / Cabela's corporate, IKEA, Best Buy, Jiffy Lube.

What we DO target (high political-sign yes-rate per campaign-strategist research):
VFW posts and veterans clubs, gun ranges and FFL dealers, hunting / fishing
shops, independent farm equipment / tractor dealers, RV parks and marinas,
independent BBQ joints and country diners, used car / motorcycle / boat lots,
independent hardware (Ace), independent auto repair / tire shops, real estate
and insurance independent agents, country stores, fairgrounds, farms, antique
malls, alcohol / tobacco shops, contractor yards (roofing, electrical, etc.).

## Quick Start

```bash
cd campaign-ops
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Pipeline (run in order)

```bash
# 1. Pull candidate pool from OSM (~60-90 min uncached, ~5 min cached)
python scripts/find_sign_locations.py

# 2. Enrich phone / email / website POCs from OSM tags + Yelp
#    YELP_API_KEY env var optional but recommended (free, 5,000 calls/day)
#    Get one: https://www.yelp.com/developers
YELP_API_KEY=xxx python scripts/enrich_pocs.py

# 3. Pick the actual 2,000 primary deployment plan + ~500 replacement bench
python scripts/select_sign_deployment.py

# 4. Per-REC yard sign allocation with POCs (4,000 plan AND boss's 7,485)
python scripts/allocate_yard_signs.py

# 5. Build the interactive deployment map
python scripts/build_candidate_map.py --with-heatmap

# 6. Quality-control report
python scripts/qc_report.py

# 7. Refresh Dashboard + Directory_Audit + feedback loop
python scripts/refresh_master.py
```

Steps 1+2 are slow; 3-7 take seconds.

## Updating from a newer boss file

```bash
cp /path/to/new_florida_sign_operations_master_*.xlsx outputs/campaign_ops_master.xlsx
python scripts/refresh_master.py
```

⚠ This **overwrites your operational data** if the boss's file is newer than
your edits. If you've added rows to `Yard_Sign_Deliveries` etc., copy them
out before overwriting.

## Interactive map: `outputs/sign_candidates_map.html`

After running `build_candidate_map.py`, open the HTML file in any browser. No
server needed. Features:

- **2,500+ pins** (2,000 primary deployment + ~500 replacement), clustered
- **Color-coded by Strategic Tier**: red=A, orange=B, blue=C, gray=D
  - **Replacement** pins use a faded light-gray icon
- **Icons by Type**: 🛣 intersection, 🏪 commercial, 🚜 agri/civic
- **Toggleable layers** (top-right): 24 layers (Plan × Type × Tier)
  - **Primary Tier A and B layers shown by default**
  - Replacement layers off by default — toggle on after refusals come in
- **Click any pin** for: name, candidate ID, county, tier, address, **phone**,
  **email**, **website**, "Open in Google Maps" link, and a search-for-contact
  fallback when POC is incomplete
- Optional **heatmap layer** (`--with-heatmap`) shows candidate density

## POC Enrichment — How It Works

`enrich_pocs.py` does NOT hallucinate phone numbers. Every value traces to a
named source. Three-tier waterfall:

1. **OSM tags** (instant, ~25-35% hit rate): pulls `phone`, `contact:phone`,
   `email`, `contact:email`, `website`, `contact:website` straight from the
   OpenStreetMap feature. Phone validated via `phonenumbers` library, must be
   `is_valid_number()`. FL area codes recognized; toll-free flagged
   "(toll-free)"; out-of-state flagged "(out-of-state — verify)".

2. **Yelp Fusion API** (rate-limited, ~10 min for 2,000 rows): for each row
   without a phone, searches Yelp by `(business name, lat, lon, radius=200m)`.
   Accepts the top result ONLY if both `rapidfuzz.token_set_ratio >= 75` AND
   the result is within 150m of the OSM point. Otherwise drops it. Free tier
   = 5,000 calls/day (well above 2,000 needed).

3. **Click-to-search URLs** (always generated): every row gets
   `Google_Search_URL`, `Yelp_Search_URL`, `Sunbiz_Search_URL` so field staff
   can one-click look up POCs at call time for the residual rows.

Each row gets a `POC_Status` label: `verified_full` (phone + email),
`verified_phone`, `verified_email`, or `needs_lookup`.
